# Habits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner is told when to do what through the day, ticks each thing with one tap, and sees at the end of the day what was earned and where points were lost.

**Architecture:** A habit day is a row with a frozen copy ("snapshot") of each routine item that applied that day: its points, rules and time window. Marks (taps) and skips are stored separately; outcome and score are always computed from snapshot plus marks by pure functions in `@pa/shared`, so correcting a past day never uses today's rules. The current day's snapshot is refreshed when the routine or settings change; an ended day is frozen. Reminders are planned one habit day at a time as `once` reminders in the existing engine, and a gate drops any whose item is already done or skipped.

**Tech Stack:** As Foundation and Money. Adds `adhan` (prayer time calculation) to `apps/api`.

**Spec:** `docs/superpowers/specs/2026-11-13-habits-design.md` and `docs/superpowers/specs/2026-11-13-overview-design.md`. Read both before any task. The Foundation and Money plans and code set the conventions.

## Global Constraints

- Everything in the Foundation and Money Global Constraints still applies (package scope `@pa/`, browser only calls `/api/*`, sentence-case copy, design tokens, new API modules imported before `FallbackModule`, new Prisma models added to `TABLES` in `apps/api/test/helpers.ts`, commit per task, motion built into each screen and off under reduced motion).
- Points are whole **hundredths of a point** (integers) in storage, the API and `@pa/shared`: a 5-point item is `500`. Only the web app converts, at the edge. Half of 5 is `250`; a miss is `-750`.
- A habit day is named by the calendar date it starts on, `YYYY-MM-DD`, and runs from `habits.dayEndHour` (starting value 4) on that date to the same hour the next date, in `general.timezone`. A time of day earlier than the day-end hour (01:00) belongs to the following calendar date but the same habit day.
- Nothing is hard-coded: the routine, points, late share (0.5), miss multiplier (1.5), day-end hour (4), daily target, warning lead (10 minutes), prayer method (Karachi) and Asr rule (Hanafi) and the summary are data or settings. The starting routine is seed data created once.
- Removing an item archives it. Past days keep their snapshot of it.
- Prayer times are calculated on the back end with `adhan`. No outside service is called.
- An item only counts from the habit day it was created on. Days before the app existed are never scored as missed.
- On the owner's machine, stop the web dev server before running the full web test suite or a build (low memory).

## Review Focus

1. Ticking at 01:00: the mark lands on the habit day that began the previous morning, and "sleep by 23:30" is late, not missed and not on the next day. Tests in Tasks 2 and 4.
2. Editing an item's points, window or days after days have passed: past days' scores and outcomes do not change; today's does. Deleting an item leaves it on past days. Tests in Task 4.
3. A day the app was never opened (no snapshot exists) between two used days: it is created on the next read with every applicable item missed, unless it was skipped; days before the first item existed are not created. Test in Task 4.
4. Two quick taps on a one-off item make one mark, and an undo followed by a tap works; a repeating item accepts taps past its target without scoring more than full points. Tests in Tasks 2, 4 and 7.
5. A day where nothing applies, or every item is skipped: score 0, possible 0, no division by zero in the target, the day is neither won nor lost, and streaks are untouched. Tests in Tasks 2 and 5.

### Task 2: Habit maths

**Files:** Create `packages/shared/src/habits.ts`, `habits.test.ts`. Export from `index.ts`.

**Interfaces — produces:**

```ts
export const PRAYERS = ['fajr', 'zuhr', 'asr', 'maghrib', 'isha'] as const;
export type Prayer = (typeof PRAYERS)[number];
export type Timing =
  | { kind: 'fixed'; start?: string; due?: string }                        // 'HH:mm'
  | { kind: 'prayer'; prayer: Prayer; start?: string; end?: string }        // optional narrower window
  | { kind: 'repeating'; start: string; end: string; everyMinutes: number; target: number };
export type AppliesTo = { kind: 'weekdays'; days: number[] } | { kind: 'dayTypes'; dayTypeIds: string[] };
export interface PrayerTimes { fajr: Date; sunrise: Date; zuhr: Date; asr: Date; maghrib: Date; isha: Date }
export interface DayContext { timeZone: string; dayEndHour: number; prayers: PrayerTimes }
export interface ItemWindow { opensAt: Date | null; dueAt: Date }
export type Outcome = 'onTime' | 'late' | 'missed' | 'pending' | 'skipped';
export interface ScoreRules { points: number; lateShare: number; missMultiplier: number }

habitDayOf(instant: Date, timeZone: string, dayEndHour: number): string
habitDayBounds(day: string, timeZone: string, dayEndHour: number): { start: Date; end: Date }
resolveTime(day: string, time: string, timeZone: string, dayEndHour: number): Date   // 01:00 resolves to the next calendar date
appliesOn(appliesTo: AppliesTo, day: string, weekPattern: Settings['general.weekPattern']): boolean
windowFor(timing: Timing, day: string, context: DayContext): ItemWindow
outcomeFor(input: { timing: Timing; window: ItemWindow; marks: Date[]; skipped: boolean; now: Date; dayEnd: Date }): Outcome
scoreFor(rules: ScoreRules, outcome: Outcome): number
summariseDay(items: { rules: ScoreRules; outcome: Outcome }[], targetPercent: number):
  { score: number; possible: number; lost: number; target: number; won: boolean | null }
streak(days: ('done' | 'missed' | 'skipped')[]): { current: number; best: number }   // oldest first
nudgeTimes(timing: Extract<Timing, { kind: 'repeating' }>, day: string, context: DayContext): Date[]
```

Rules the signatures do not fix:
- `windowFor` fixed: `opensAt` from `start` or null; `dueAt` from `due`, or the day's end when there is none. Prayer: opens at that prayer, due at the next prayer's start (Fajr due at sunrise, Isha due at the day's end); a given `start`/`end` replaces the matching edge. Repeating: `start` to `end`.
- `outcomeFor`, one-off items: skipped wins; the earliest mark at or before `dueAt` is on time (a mark before `opensAt` also counts as on time); a later mark is late; no mark is `pending` before `dayEnd` and `missed` from `dayEnd` on.
- `outcomeFor`, repeating: marks at or above `target` is on time at any moment; otherwise `pending` before `dayEnd`; at `dayEnd`, at least `Math.ceil(target / 2)` marks is late, fewer is missed.
- `scoreFor`: on time `points`; late `Math.round(points * lateShare)`; missed `-Math.round(points * missMultiplier)`; pending and skipped `0`.
- `summariseDay`: `possible` is the sum of `points` over items that are not skipped; `lost` is `possible − score` counting only decided items (not pending); `target = Math.round(possible * targetPercent / 100)`; `won` is null when `possible` is 0, else `score >= target`.
- `streak`: skipped days neither add nor break; `current` counts back from the newest day.

- [ ] **Step 1:** Tests, with `Asia/Dhaka`, day-end 4 and fixed prayer times: `habitDayOf` for 03:59 and 04:00 local (previous and same day); `resolveTime('2026-11-15', '01:00')` is 16 Nov 01:00 local; breakfast due 08:30 done 08:30 on time, 08:50 late, none before day end pending, none after missed; a no-due item done at 03:30 next morning on time; sleep due 23:30 marked 01:00 late; Fajr window ends at sunrise, Zuhr narrowed to 13:00–13:30, Isha due at day end; scores `500 / 250 / -750` and with overrides `lateShare 0.8`, `missMultiplier 1` give `400 / -500`; repeating target 8: 8 and 9 marks on time, 4 late, 3 missed, 5 marks mid-day pending; `summariseDay` for a mixed day, for all skipped (`possible 0`, `won null`), and for pending items; `streak(['done','skipped','done','missed','done','done'])` is `{ current: 2, best: 2 }` and `['done','done','skipped','done']` is `{ current: 3, best: 3 }`; `appliesOn` for weekdays and for a day type against the default week pattern; `nudgeTimes` every 90 minutes 09:00–21:00 gives 9 instants.

### Task 4: Days, marks and skips

**Interfaces — consumes** Task 2 maths, `ItemsService`, `prayerTimesFor`. **Produces:**
