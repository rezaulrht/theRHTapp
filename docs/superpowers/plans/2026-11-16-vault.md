# Vault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Course files, saved AI answers, work files and their reminders live in one place, filed in the owner's own folders, found again by browsing, tags, fields or search.

**Architecture:** Folders and items (file, note, link) are rows in the shared database; file bytes live in a private Cloudflare R2 bucket and travel straight between the browser and R2 on short-lived signed addresses the back end issues. Storage sits behind a `FileStorage` interface with an R2 implementation for production, a local-disk one for development (so the app works before the owner gives R2 keys), and a fake for tests. Field filtering and sorting, path checks and calendar maths are pure functions in `@pa/shared`. Trash is a timestamp plus the id of what was deleted, so a folder and everything in it is restored or purged together.

**Tech Stack:** As before. Adds `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` to `apps/api`; `react-markdown` and `remark-gfm` to `apps/web`.

**Spec:** `docs/superpowers/specs/2026-11-13-vault-design.md` and `docs/superpowers/specs/2026-11-13-overview-design.md`. The Foundation, Money and Habits plans and code set the conventions.

## Global Constraints

- Everything in the earlier plans' Global Constraints still applies (`@pa/` scope, browser only calls `/api/*` plus the signed storage addresses, sentence-case copy, design tokens, new modules before `FallbackModule`, new models in `TABLES`, commit per task, motion in every screen, off under reduced motion).
- Nothing is fixed: no built-in Subject/Chapter/Topic, no fixed fields. Education and work are just top-level folders the owner makes. The only seed is an empty Vault.
- The bucket is private. File addresses are signed and short-lived (upload 15 minutes, download 5 minutes). Secrets come from env only: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`. Without them the API uses the local-disk storage in development and refuses uploads in production with `File storage is not set up yet`.
- Settings: `vault.maxFileMb` 100 (1 to 5000), `vault.trashDays` 30 (1 to 365). Storage allowance shown against is 10 GB (a constant, the R2 free tier).
- Opening files: PDF, images, markdown and plain text open in the app; everything else downloads (Word and PowerPoint included; to be confirmed with the owner).
- Search covers folder and item names, note text, link titles and addresses, tag names and custom field values. Not file contents.
- Deleting moves to trash. Only emptying the trash, or the trash period passing, removes rows and stored files for good.
- On the owner's machine: stop the web dev server before full web test runs or builds; rebuild the API before checking back-end changes in the browser (the preview runs `dist`).

## Review Focus

1. Moving a folder into itself or any folder inside it is refused with a plain message; moving several things at once where one would make a loop moves none of them. Tests in Tasks 1 and 2.
2. A file whose upload never finished (closed tab, lost signal) is not shown as a usable item and is cleaned up after a day; a file larger than the limit is refused before any upload starts and again on completion if the stored size is larger. Tests in Task 3.
3. Restoring something from the trash whose folder is itself in the trash or gone: it comes back to the top level, not into a hidden folder. Tests in Task 5.
4. A custom field deleted or changed type after values were given: old values are kept and shown as text, never crash a filter or sort; filtering by a choice that no longer exists matches nothing. Tests in Tasks 1 and 4.
5. Names with Bangla text, quotes, slashes and emoji in folders, notes and file names, including in search and in the download file name. Tests in Tasks 2, 3 and 4.

### Task 3: Files

**Files:** Create `storage/file-storage.ts`, `storage/r2-storage.ts`, `storage/local-storage.ts`, `files.ts`, `test/vault-files.e2e-spec.ts`. Modify `env.ts`, `.env.example`, `docs/setup/accounts.md` (R2 bucket, keys and the bucket CORS rule for the web origin, `PUT` and `GET`).

**Produces:**

```ts
export interface FileStorage {
  ready: boolean;                                   // false: uploads refused with "File storage is not set up yet"
  uploadUrl(key: string, mimeType: string, size: number): Promise<{ url: string; headers: Record<string, string> }>;
  downloadUrl(key: string, fileName: string, inline: boolean): Promise<string>;
  size(key: string): Promise<number | null>;        // null: no such object
  read(key: string, maxBytes: number): Promise<Buffer>;
  remove(key: string): Promise<void>;
}
export const FILE_STORAGE = Symbol('FILE_STORAGE');
```

- Key: `vault/<itemId>/<random>`. Never the file name.
- `POST /api/vault/files { folderId, name, size, mimeType }` → `{ item, upload: { url, headers } }`, item `uploaded: false`. Refused over `vault.maxFileMb`.
- `POST /api/vault/files/:id/complete` → checks the stored size exists and is within the limit, else deletes the object and the item and answers 400. Marks `uploaded`.
- `GET /api/vault/files/:id/url?inline=1` → `{ url }` (signed, `Content-Disposition` with the file name, UTF-8 safe).
- `GET /api/vault/files/:id/text` → the text of a markdown or plain file up to 2 MB.
- `GET /api/vault/storage` → `{ used, allowance: 10 * 1024 ** 3, files }` over uploaded files, trash included.
- Unfinished uploads older than 24 hours are removed by the hourly cleanup (shared with Task 5's cron).
- Local storage (development only): files under `.localfiles/`, addresses `/api/vault/local/:token` (PUT and GET) with an HMAC token naming key, method and expiry.

- [ ] **Step 1:** Tests with a fake storage: the upload flow ends with a usable file; listing hides unfinished uploads (Review Focus 2); over-limit refused up front, and at completion when the stored object is larger (object removed); a Bangla file name in the download disposition; text read for markdown, refused for PDF; storage used sums sizes; unfinished upload cleanup; storage not ready answers the plain message. Local storage: PUT then GET round-trip, expired or altered token refused.
