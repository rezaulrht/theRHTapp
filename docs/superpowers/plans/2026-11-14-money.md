# Money Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner can stop using the paper notebook: log spending in seconds from the phone, see every account's balance, and see where each month's money went.

**Architecture:** Every entry stores its signed effect on an account (`accountDelta`, and `toAccountDelta` for transfers), so a balance is always opening balance plus a sum, whatever the entry kind. All money maths (balances, month summaries, comparisons, budget state) are pure functions in `@pa/shared`, tested without a database; the API loads rows and calls them; the web app displays results.

**Tech Stack:** As Foundation. Adds Recharts for the month chart.

**Spec:** `docs/superpowers/specs/2026-11-13-money-design.md` and `docs/superpowers/specs/2026-11-13-overview-design.md`. Read both before starting any task. Foundation's plan and code set the conventions.

## Global Constraints

- Everything in Foundation's Global Constraints still applies (package scope `@pa/`, secrets from env, browser only calls `/api/*`, sentence-case copy, design tokens, commit per task).
- Amounts are whole paisa (integers) everywhere in storage, the API and `@pa/shared`. 1 taka = 100 paisa. Only the web app converts, at the edge: `toPaisa("12.50") === 1250`, `fromPaisa(1250) === 12.5`.
- A date on an entry is a calendar day, `YYYY-MM-DD`, in the settings time zone. It is never a timestamp. "Today" is today in `general.timezone`.
- Balances are never stored. They are computed from `openingBalance` and entry deltas.
- Nothing is hard-coded: accounts, categories, shortcuts, budgets, people, warning percentage and reminder time are data or settings. Bank, bKash, Cash and the six starting categories are seed rows created once, then fully editable.
- Archiving hides a thing from pickers but keeps its history. Nothing with entries is ever hard-deleted.
- New API modules are imported in `app.module.ts` **before** `FallbackModule`.
- New Prisma models are added to the `TABLES` list in `apps/api/test/helpers.ts`.
- Motion is part of each screen's task, not a later pass: masked heading reveals, staggered arrivals, `Amount` counting up, charts drawing in. Reuse `apps/web/src/components/motion/`. Nothing delays a tap; all of it is off under reduced motion.
- On the owner's machine, stop the web dev server before running web tests (low memory).

## Review Focus

1. Editing or deleting a past entry: every balance and every month figure that included it changes accordingly, including a transfer's fee. Tests in Tasks 2 and 4.
2. Entering an amount by hand: `12.5`, `12.50`, `1,250`, `.5`, ` 80 ` are accepted; `abc`, `-5`, `0`, `12.345`, an empty field and an amount over 20,000,000 are refused with a plain message and nothing is saved. Tests in Tasks 2 and 7.
3. Archiving an account or category that existing entries use: old entries still show its name; it no longer appears in pickers; an archived account's balance is still shown in history but leaves the balance strip. Tests in Tasks 3 and 9.
4. A month with no entries, and the first month ever (no previous month to compare): totals are zero, comparison says "no earlier month to compare" and nothing divides by zero. Tests in Task 2.
5. Two taps on a shortcut, or a double-submitted form: two entries are created (that is what was asked), but the button is disabled while saving so one tap makes one entry. Test in Task 8.

**Interfaces — produces:**

```ts
export type EntryKind = 'expense' | 'income' | 'transfer' | 'correction' | 'loan';
export type LoanDirection = 'lent' | 'borrowed' | 'repaid_to_me' | 'repaid_by_me';
export const MAX_AMOUNT = 2_000_000_000;            // paisa: 20,000,000 taka

/** The stored shape the maths needs. Dates are 'YYYY-MM-DD'. Amount is positive paisa. */
export interface LedgerEntry {
  id: string; kind: EntryKind; date: string; amount: number;
  accountId: string; accountDelta: number;
  toAccountId: string | null; toAccountDelta: number | null;
  categoryId: string | null; personId: string | null; loanDirection: LoanDirection | null;
}

export function parseAmount(input: string): { ok: true; paisa: number } | { ok: false; message: string };
export function deltasFor(kind: 'expense' | 'income' | 'transfer', amount: number): { accountDelta: number; toAccountDelta: number | null };
export function loanDelta(direction: LoanDirection, amount: number): number;   // effect on the account
export function balanceOf(account: { id: string; openingBalance: number }, entries: LedgerEntry[]): number;
export function owedBy(personId: string, entries: LedgerEntry[]): number;      // positive: they owe the owner; negative: the owner owes them

export interface MonthSummary {
  month: string;                                       // 'YYYY-MM'
  spent: number; income: number;
  byCategory: { categoryId: string | null; spent: number; share: number }[];   // largest first; share 0..1
}
export function summariseMonth(month: string, entries: LedgerEntry[]): MonthSummary;

export interface Comparison { current: number; previous: number | null; change: number | null; percent: number | null }
export function compare(current: number, previous: number | null): Comparison;

export function spendingByDayType(
  entries: LedgerEntry[], weekPattern: Settings['general.weekPattern'],
): { dayTypeId: string; total: number; days: number; average: number }[];

export type BudgetState = 'ok' | 'warning' | 'over';
export function budgetState(spent: number, budget: number, warnPercent: number): BudgetState;
export function monthOf(date: string): string;                 // '2026-11-13' -> '2026-11'
export function previousMonth(month: string): string;          // '2026-01' -> '2025-12'
export function todayIn(timeZone: string, now?: Date): string; // 'YYYY-MM-DD'
```

Rules the tests pin:
- `parseAmount`: trims; allows thousands commas; at most two decimals; must be greater than 0 and at most `MAX_AMOUNT`. Messages: `Enter an amount`, `Enter a number, like 80 or 12.50`, `Use at most two decimal places`, `Enter an amount above zero`, `That amount is too large`.
- `deltasFor`: expense `-a`; income `+a`; transfer `-a` and `+a`.
- `loanDelta`: lent `-a`, borrowed `+a`, repaid_to_me `+a`, repaid_by_me `-a`. `owedBy`: lent `+a`, repaid_to_me `-a`, borrowed `-a`, repaid_by_me `+a`.
- `summariseMonth`: `spent` is the sum of `amount` over `expense` entries in the month (fees are expenses, so they count). `income` sums `income` entries. Transfers, corrections and loans count in neither. `share` is 0 when `spent` is 0.
- `compare`: `previous === null` gives `change` and `percent` null; `previous === 0` gives `percent` null (no division by zero) and `change = current`.
- `spendingByDayType`: `days` is the number of distinct dates with an expense for that day type; `average = Math.round(total / days)`; day types with no spending are omitted.
- `budgetState`: `over` when `spent > budget`; `warning` when `spent * 100 >= budget * warnPercent`; else `ok`. A budget of 0 is `over` once anything is spent, `ok` otherwise.

### Task 4: Entries

**Files:** Create `entries.controller.ts`, `entries.service.ts`, `test/money-entries.e2e-spec.ts`.

**Interfaces — consumes** `deltasFor`, `MAX_AMOUNT`, `todayIn`. **Produces:**

- Entry JSON: `{ id, kind, date, amount, name, note, accountId, toAccountId, categoryId, personId, loanDirection, feeOfId, fee: { id, amount } | null, createdAt }`. `date` is `YYYY-MM-DD`.
- `POST /api/money/entries`, body by `kind`:
  - `expense`: `{ kind, date?, amount, name, accountId, categoryId, note? }`
  - `income`: `{ kind, date?, amount, name, accountId, note? }`
  - `transfer`: `{ kind, date?, amount, accountId, toAccountId, fee?, note? }` — `name` is generated (`Bank to Cash`). `fee` (paisa, optional, above 0) creates a linked expense in the Fees category, paid from `accountId`, named `Fee: Bank to Cash`. Accounts must differ.
  - `correction`: `{ kind, date?, accountId, trueBalance, note? }` — `accountDelta = trueBalance - current balance`; `amount = |delta|`; refused with 400 `That is already the balance` when the delta is 0.
  - `date` defaults to today in the settings time zone; a date in the future is refused (`Pick today or an earlier date`).
  - Amount: integer, 1 to `MAX_AMOUNT`. Account and category must exist and not be archived (400 naming the field). All of one request is saved in one transaction.
- `PATCH /api/money/entries/:id`: same fields as creation for that kind (kind cannot change). Deltas are recomputed. For a transfer, `fee: 0` or `null` removes the fee entry, a number creates or updates it. A fee entry is not edited directly (400 `Edit the transfer to change its fee`). A correction's `trueBalance` cannot be edited; only its `date` and `note`.
- `DELETE /api/money/entries/:id` → 204. Deleting a transfer deletes its fee. Deleting a fee alone is allowed.
- `GET /api/money/entries?date=YYYY-MM-DD` (one day) or `?from=&to=` (inclusive), optional `accountId`, `categoryId`, `q` (case-insensitive match on name and note), `limit` (default 200, max 1000). Newest date first, then newest created first. Loan entries are included.
- `GET /api/money/entries/names?q=` → up to 8 `{ name, accountId, categoryId, amount }` from the most recent distinct expense names starting with or containing `q`, for the suggestion list.
- `EntriesService.ledger(): Promise<LedgerEntry[]>` for the maths functions.
